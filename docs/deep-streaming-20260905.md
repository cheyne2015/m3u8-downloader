# 深度提取即时显示：第一轮优化

范围：空闲时启动的深度提取尽早显示候选，后台补全结果和估算；扫描期间可下载，停止提取不影响下载。下载期间预载的下一网页，链接和标题在当前下载结束后一起交接。基础版本为 `35baa0b`。本轮修改源码，不更新已安装的 EXE。

## 行为变化

- 空闲时启动深度提取，浏览器发现 m3u8 即报告，GUI 每 100 ms 接收消息，无需等待整轮扫描和大小估算。
- 按 URL 追加或更新行，保留行号、选择和滚动位置；流式 GUI 不按大小重新排序。CLI 最终结果仍保持原来的排序。
- 大小、时长估算逐条更新，较慢的候选不阻挡已完成的估算。
- 新增独立的“停止提取”按钮。扫描和下载分别持有停止信号，启动任一任务不会清除另一任务的停止请求。
- 停止提取保留已显示的结果；已发出的大小探测在后台收尾，结束后释放自建 HTTP 会话，不再更新界面。扫描中的下载任务使用启动时确定的链接和文件名。

## 接口与维护

`extract_m3u8_from_page_with_title(..., on_candidate=callback)` 是可选增量入口。回调在调用线程执行，应快速返回；同一 URL 可能再次报告元数据更新。GUI 将候选复制到消息队列，只在 Tk 主线程更新控件。

独立 worker 增加可选 `--stream`：逐行输出候选事件，最后输出完整 `urls/title` JSON；无参数时保持原协议。父进程持续读取 stdout/stderr，避免等待退出期间输出管道堵塞。

普通模式保留原来的提取方式。普通和深度模式在下载期间启动预载时，都暂存下一网页的结果与标题，当前下载结束后一起显示和回填文件名；不提前替换当前列表、选中项或文件名。普通模式、CLI 和既有 API 调用无需新增参数。

### 预载回归修复

第一轮实现把深度预载也当作即时扫描：开始时清空当前列表，提取完成后只发送标题消息，而 GUI 在下载期间忽略该消息，导致下载结束后无法回填标题。

修复后，在启动提取时确定是否属于预载。预载的候选和标题通过一条消息交给 Tk 主线程：下载仍在进行就共同暂存，下载已经结束就共同显示。下载结束的回调也在主线程消费暂存结果，避免提取完成与下载结束的先后顺序导致遗漏。

回归测试使用真实本地下载和 Tk 控件，覆盖深度/普通模式以及“预载先完成”“下载先完成”四种组合，验证当前列表、选择和文件名保持不变，交接后下一网页链接和标题一致，当前下载文件内容完整。

## 界面与功能优化

日志区保持常显，继续作为详细状态和故障证据来源。本轮在原布局上增加三组常用信息：

- 提取结果下方显示总候选数和已选数，并提供“全选”“取消选择”“复制链接”；复制多条时按列表顺序写入剪贴板，每行一条。
- 预载独立显示“正在提取”“成功并等待下载结束”“已载入”“失败/停止”，不覆盖下载进度。链接和标题仍在当前下载结束后一起交接。
- 下载进度区固定显示当前网页标题和实际保存文件名。下载任务会分别保存标题与路径，因此手动命名、批量编号或自动改名不会把标题改成文件名；串行队列切换任务时同步更新，队列结束后恢复为空闲状态。

真实 Tk 界面已在 980 x 900 默认尺寸启动并目视检查：新增工具栏、预载状态、下载信息完整可见，日志区未折叠。界面截图保存在 Codex 本次可视化目录的 `m3u8-gui-optimized.png`。

复查后补强：带停止信号的深度提取由父进程监管独立 worker，因此 Playwright 即使阻塞在页面导航中也可被及时终止；测试页模拟 20 秒不返回导航，停止操作在 2 秒上限内完成。源码运行时优先用当前 Python 启动 worker，不依赖 `py/python` 是否加入 PATH。增量大小估算使用独立复制的 HTTP 会话，连同自定义 adapter 与 hook 一起复制，调用者停止后可安全关闭或复用自己的会话。普通模式也只按启动提取时的状态判断是否属于预载，不会因稍后开始下载而改变交接方式。深度候选提前出现并立即开始下载时，稍后取得的完整网页标题会补写到当前任务和同页等待队列；文件名仍使用适合保存的标题截取段。
