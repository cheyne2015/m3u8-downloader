# 深度提取识别路径改进

分析来源为用户提供的 m3u8-downloader 0.10.1 用户脚本。该脚本在页面加载开始时
包装 XMLHttpRequest，在 open 调用中发现包含 .m3u8 的地址；随后另发请求检验内容。
它还轮询 video.currentSrc 发现 MP4。这段脚本没有监听 fetch，也没有支持无后缀
的播放列表。识别率差异不能仅凭脚本静态分析量化。

## 本次实现

- 保留响应监听，增加导航前的浏览器原生请求监听，覆盖 XMLHttpRequest 和 fetch。
- 只暂存疑似 m3u8 地址，继续沿用候选去重及下游元数据有效性检验。
- 在原有收集预算内，对主页面及内嵌页面的视频元素尝试一次静音播放，触发延迟请求。
  使用 WeakSet 避免重复调用，不点击网页按钮。
- 扫描已加载的内嵌页面内容，以该页面地址解析相对链接。
- 同时覆盖进程内、单次 worker 和常驻异步服务路径。Chromium 池和任务并发规则不变。

## 验证与限制

`tests/test_deep_discovery.py` 通过公开提取接口和本地 HTTP 服务验证四个无响应请求、
内嵌页面相对地址，以及四个播放后延迟请求，两种生产入口均需通过。
这些测试验证地址发现，不代表失败请求对应的视频可以下载。

静音播放失败时忽略异常，仍继续原有识别；需要登录、点击自定义播放器按钮、
超出收集预算才加载、无 .m3u8 后缀等情况不承诺覆盖。
没有导入用户脚本的下载界面、第三方统计、远程代码执行和 XMLHttpRequest 构造函数替换。

安装版优先使用外置 deep-runtime/deep-worker.exe。因此后续打包部署必须同时更新
深度组件中的 worker，单独替换主程序不能让安装版获得本次常驻服务改进。
浏览器内核无需重新下载。
