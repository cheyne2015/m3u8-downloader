# m3u8 下载器 v2 架构

## 目标

把旧版集中在 Tkinter 主类中的界面状态、队列、下载控制和持久化拆成可独立测试的层。图形界面只渲染状态并发送用户命令，不直接编排线程或修改 JSON。

## 分层

```text
PySide6 界面
  └─ 应用服务（创建、暂停、继续、选择、删除、重命名）
       ├─ 任务调度器（提取槽、下载槽、顺序、重试）
       ├─ 任务仓库（SQLite）
       ├─ 提取适配器（复用 extractor）
       ├─ 下载适配器（复用 downloader）
       ├─ 文件服务（命名、空间、删除、重新关联）
       └─ Windows 服务（单实例、托盘、通知、用户级加密）
```

## 领域对象

### 父任务

- 唯一编号
- 原始地址与地址类型
- 显示名称、原始网页标题、保存目录
- 提取状态与下载状态
- 调度顺序与优先级
- 是否由用户接管候选选择
- 创建、开始、完成、更新时间
- 任务配置快照
- 汇总进度与错误

### 子下载项

- 唯一编号与父任务编号
- m3u8 地址、候选标题、来源和提取模式
- 是否选中、处理状态和队列顺序
- 预估/实际大小、时长、进度、速度
- 输出路径和临时缓存身份
- 重试次数与最后错误

## 状态原则

- 提取状态和下载状态正交保存，避免用一个字符串表达同时提取与下载。
- 所有状态变化通过应用服务执行并写入数据库。
- 调度器依据持久化状态选择工作，不以界面控件状态作为事实来源。
- 工作线程只产生事件；事件由单一协调器顺序落库，降低竞态。
- 程序启动先把遗留运行态转换为已暂停，再创建任何网络工作。

## 首个纵向切片

公共入口：`TaskService.create_tasks(request)`。

输入多行地址和保存目录后：

1. 清理空行和重复地址。
2. 为每个地址创建父任务。
3. 识别明显的 m3u8 地址并设为等待下载；其他地址设为等待提取。
4. 生成安全的初始任务名。
5. 保存任务配置快照、创建时间和调度顺序。
6. 通过 SQLite 仓库重新读取时得到相同结果。

这个切片先建立稳定的数据边界，后续调度器和界面都只依赖该公共服务。
