# LenTV 真实网站验证（2026-09-11）

## 验证范围

使用 Python 3.13、Playwright 和本机 Chromium，按新版程序的“智能模式”实际执行
深度提取、候选流式回传、媒体信息估算、阈值处理和单分片下载。测试未下载完整影片；
下载链路在完成一个真实分片后主动停止，以验证取消和缓存收尾。

## 真实下载发现与修复

短视频页面提取出的媒体清单在离开来源页一段时间后会返回 HTTP 403。逐项排除
Referer、User-Agent、Origin、Cookie 和浏览器提示头后确认：该站点依赖访问来源页后
形成的短期媒体放行窗口，并非依赖某一个可复制的固定请求头。

修复后的网页任务在媒体清单首次返回 403 时会：

1. 立即停止同请求的无效重试；
2. 自动用深度模式重新访问原网页一次；
3. 如果网页当前只返回一个候选，则使用刷新后的媒体地址；
4. 重新请求媒体清单一次。

真实复测中，程序成功触发来源页刷新、解析媒体清单并下载一个实际分片，随后按测试
信号主动停止；总耗时约 10.7 秒。m3u8 直链不会触发网页刷新逻辑。

## 标题编码

测试终端最初把中文标题显示为乱码。分别检查 HTTP 文本、Playwright `page.title()`
和深度子进程 JSON 后，三层 Unicode 内容完全一致；程序保存的中文标题正确，乱码只
发生在测试终端显示层，因此没有修改应用的标题编码。

## 本轮性能策略

少于 100 条候选时继续使用原来的三分片抽样精度和用户配置的估算并发数。达到 100 条
候选时，估算使用 16 路并发和单分片抽样；清单总时长仍由完整 m3u8 精确累计，体积为
快速近似值。这只影响大量候选的媒体信息估算，不改变下载线程数和下载速度设置。
