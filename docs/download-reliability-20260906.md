# 下载速度、稳定性与核心复用优化

日期：2026-09-06  
基线：`9d6c201`

## 修复的问题

旧下载器把网络响应直接写入最终的 `seg_XXXXX.ts`。连接中途断开时会留下非零残片；程序下次启动只检查“文件存在且非空”，可能把残片误当作已完成片段。所有任务还共用同一个 `.tmp` 命名空间，不同播放列表在失败后可能复用同名旧片段。

GUI 另行复制了解析 master playlist、下载密钥、并发下载、解密、合并与统计流程。核心下载器的错误修复不会自动覆盖 GUI，两个入口已经出现维护漂移。`重试次数=0` 还会导致片段一次请求都不发出；播放列表和 AES 密钥没有使用配置的重试次数。

加密播放列表未显式给出 IV 时，旧实现对所有片段都使用全零 IV。HLS 要求使用该片段 media sequence number 的 128 位大端表示，因此 sequence 非零的 AES-128 流可能解密错误。

## 实现

- 片段先写入 `.part`，完整响应结束并校验 `Content-Length` 后用 `os.replace` 原子发布为 `.ts`。停止或网络失败不会产生伪完成片段。
- 重试时检测 `.part` 大小并发送 `Range: bytes=N-`；服务端正确返回 `206` 与匹配的 `Content-Range` 时追加剩余部分，忽略 Range 返回 `200` 时安全地从头覆盖。错误的 `Content-Range` 会被拒绝并重新完整下载；服务器用 `416` 确认本地 `.part` 已达到总长度时可直接发布，长度不同时清除旧残片再从零下载。
- 每个输出任务使用独立的缓存子目录。缓存身份包含片段 URL、sequence、密钥方法、密钥 URI 和 IV；manifest 只保存 SHA-256 指纹，不把签名 URL 或令牌写入磁盘。不同播放列表、输出目标或加密信息不会误用同名片段。
- `重试次数` 统一解释为“首次请求后的额外重试次数”，所以设为 0 仍会执行一次请求。播放列表、AES 密钥和片段都使用同一重试/停止语义。
- 下载块从 8 KiB 调整到 64 KiB，HTTP 连接池按下载并发数配置并启用阻塞上限，减少 Python 循环和高并发下反复丢弃连接的开销。每个工作线程使用独立 Session，避免并发共享可变请求状态。
- 下载协调线程每 0.1 秒检查停止状态，不再等待所有阻塞请求才响应界面；已经进入网络读取的线程会按用户配置的原始超时自然退出，并在后台清理 Session。每次 GUI 下载拥有独立且不会被后续任务清空的停止信号，旧线程在响应返回后、改动缓存前还会再次检查，因此停止后立即重试也不会重新激活旧任务。这样既能及时结束界面任务，也不会缩短正常慢服务器的读取容忍度。
- 核心下载器新增日志、进度、停止回调。GUI 删除 177 行重复下载流程，直接调用 `M3U8Downloader.download()`；CLI 与 GUI 现在使用同一套解析、缓存、重试、下载、解密和合并代码。
- AES-128 未显式提供 IV 时，按片段 sequence 生成默认 IV。
- `setup.py` 直接读取包内 `__version__`，消除安装元数据 `1.4.0` 与程序版本 `1.5.3` 的漂移。

## 验证证据

真实本地 HTTP 测试下载 4 个片段（合计 786,438 字节），服务端第一次在第二个片段中途断开。客户端第二次发送 Range，仅获取剩余数据；合并文件与四个源片段逐字节一致，成功后临时目录被清理。

另一个真实 HTTP 测试让服务端发送 64 KiB 后持续静默；停止下载后 2 秒内退出，只保留 `.part`，不生成最终片段或视频文件。单元测试还覆盖零重试首次请求、Range 追加、错误范围拒绝、完整 `.part` 的 416 发布、停止打断 30 秒退避、任务缓存隔离、每线程独立 Session、播放列表与密钥瞬时失败重试、进度回调及 sequence 默认 IV。

最终全量测试为 **356 passed, 1 skipped**；启用了未处理线程异常与对象清理异常转测试失败的检查。`compileall`、`git diff --check` 和 `py -3.13 setup.py --version` 均通过，安装元数据版本输出 `1.5.3`。

64 MiB 本地写入循环微基准交替运行 6 轮：旧 8 KiB 循环中位数 `0.087665 s`，新 64 KiB 原子写入中位数 `0.028675 s`，循环与落盘开销下降约 `67.3%`。这是本机内存响应到临时文件的微基准，只证明客户端循环开销降低，不代表外部网站或网络带宽一定提升。

本轮只修改并验证源码，没有打包或替换正式版 EXE。
